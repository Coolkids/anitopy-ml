# 大数据分步训练

更新后的 `data.json` 有 92 条作品记录、72 个模板条目。采用同一份冻结数据、按优化器步数分段训练：每次只运行一段，保存完整状态，下次从尚未处理的样本继续。这样可以累计学习大数据，内存占用由洗牌缓冲区、批大小和梯度累积组控制。

文中的训练命令供手动执行。准备数据、训练和继续训练是三个独立操作。

## 1. 一次性准备新数据版本

下面生成 100 万条原始样本；实际保留数取决于重复文本数量。训练量可按需求调整 `--count`，输出必须使用新的空目录。

```powershell
uv run anitopy-ml data prepare-synthetic `
  --input data.json `
  --output-dir data/synthetic/V13_large_split `
  --count 1000000 `
  --seed 20261025 `
  --split-seed 20261025 `
  --optional-rate 1.0 `
  --season-rate 0.7
```

该命令逐条生成数据，以 SQLite 磁盘索引去重，逐条检查字符、实体片段和 BIO 标签，按作品键划分训练、验证和冻结测试集。只有全部作品得到覆盖、三个分区均覆盖全部 72 个模板条目时，才写出 `training_manifest.json`。同一文本若存在不同标签或作品归属，会拒绝导出。某些受条件限制的模板出现概率低，样本数太少时会明确列出缺失条目。

输出目录包含 `train.jsonl`、`validation.jsonl`、`test.jsonl` 和清单。清单记录源模板哈希、生成参数、分区文件哈希、作品归属、各分区模板频次与字段频次。全模板覆盖只保证条目出现；查看频次后仍可增加样本量，不能用样本总数代替稀有模板覆盖检查。生成期间需要为临时 SQLite 索引和最终 JSONL 同时预留磁盘空间。

数据生成后固定 `data.json`、分区和清单。训练器只读取训练、验证分区；候选与校准策略确定前，不运行冻结测试评测。

## 2. 手动执行第一段训练

配置 `configs/分步训练.json` 使用 8 次梯度累积。下面的实际批大小为 2，有效批大小约为 16；编码器梯度检查点以额外计算换取更低显存占用。它是资源受限机器的起始配置，尚未执行 GPU 训练验证，实际速度和显存需求取决于标题长度与设备。

```powershell
uv run anitopy-ml train extractor `
  --data-dir data/synthetic/V13_large_split `
  --output-dir artifacts/runs/V13_large_seed1 `
  --config configs/分步训练.json `
  --epochs 2 `
  --batch-size 2 `
  --max-length 256 `
  --device cuda `
  --seed 20261025 `
  --shuffle-buffer-size 1024 `
  --gradient-checkpointing `
  --checkpoint-steps 250 `
  --max-steps 2000
```

`--epochs 2` 是整个实验的总轮数；`--max-steps 2000` 是本次运行的优化器步数上限。每段通常处理约 32,000 条训练样本，末尾不足一个累积组时按实际微批次数归一化。每完成 100 步输出进度，每 250 步保存检查点，到达本次上限后保存并以“分段暂停”正常退出。每一整轮仍会遍历全部训练样本，不会只反复训练文件开头。

训练和验证均按批分词、读取，不会把完整数据集放进内存。每轮使用种子确定的块内洗牌；它的随机程度受缓冲区大小影响，不等同于全数据随机排列。需要降低内存时，可在首次启动前减小缓冲区。显存不足时也应在首次正式训练前调整批大小；例如批大小改为 1、配置中的梯度累积改为 16，可保持近似有效批大小。

## 3. 以后每次继续一段

参数保持一致，增加 `--resume`。每执行一次，继续最多 2,000 个优化器步，直到总轮数结束或触发早停。

```powershell
uv run anitopy-ml train extractor `
  --data-dir data/synthetic/V13_large_split `
  --output-dir artifacts/runs/V13_large_seed1 `
  --config configs/分步训练.json `
  --epochs 2 `
  --batch-size 2 `
  --max-length 256 `
  --device cuda `
  --seed 20261025 `
  --shuffle-buffer-size 1024 `
  --gradient-checkpointing `
  --checkpoint-steps 250 `
  --max-steps 2000 `
  --resume
```

恢复会读取原子保存的 `training_state.pt`，恢复模型、AdamW、混合精度缩放器、Python/Torch/CUDA 随机状态、已完成轮次、轮内批次、累计损失、验证历史和早停计数。启动时重新核对清单及训练、验证文件的真实哈希；恢复时不再分词已提交样本，但仍需顺序扫描、重放该轮此前的原始记录和洗牌顺序，因此大文件恢复存在读取开销。

可以调整本次 `--max-steps` 和 `--checkpoint-steps`，或者省略 `--max-steps` 直接完成剩余训练。数据、总轮数、批大小、累积配置、最大长度、随机种子、增强设置、洗牌缓冲区、梯度检查点开关、设备类型和 Torch/Transformers 版本必须与检查点一致。早期版本的状态文件缺少轮内进度，无法使用新 `--resume`。

断电或强制结束后，从最近成功保存的检查点恢复；未保存的步数会重做。保存采用临时文件替换，需要额外容纳一份训练状态文件。`training_state.pt` 是恢复依据，旁路元数据在异常退出时可能稍有滞后。正常分段退出会同步写出元数据和训练报告。

## 4. 查看学习进度与更新数据

```powershell
Get-Content -Encoding UTF8 artifacts/runs/V13_large_seed1/训练报告.json
```

报告包含状态、全局优化器步数、本次步数、当前轮已完成批次、当前轮平均损失和完整轮次的验证历史。整轮结束后才执行验证并更新 `best_model.pt` 与 `tokenizer/`；第一轮尚未结束时，最佳验证 F1 为空，不能把阶段性状态当成已验证模型。

修改模板或增加数据后，重新生成新版本，使用新的输出目录，必要时通过 `--init-model` 复用上个版本的 `best_model.pt`。`--init-model` 与 `--resume` 互斥：前者开启新的优化过程，后者续接同一冻结数据实验。

本文默认从基础模型开始，以保留新分区的作品隔离含义。若复用 V11 等旧模型，新验证/测试作品可能已经出现在旧模型的训练数据中；重新划分作品不能消除这类历史泄漏，相关分数只能作为更新诊断，不能宣称独立泛化结果。

不应按新增模板分别训练并仅保留最后一组数据；这种方式可能遗忘旧模板。把当前全部模板共同生成到固定训练分区，再按步数逐段遍历，可同时保留新旧结构的学习机会。模板分布内的覆盖和验证分数也不能代表真实发布标题准确率。
