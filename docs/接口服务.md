# 本地 Web API 服务

服务使用 Django 提供 JSON 接口，不使用数据库、不上传标题，也不会在运行时下载模型。模型在本进程首次请求时加载，随后由同一进程复用；启动多个工作进程会重复占用模型内存，因此默认只使用一个 Gunicorn 工作进程。

完整机器可读契约见 [接口定义.openapi.yaml](接口定义.openapi.yaml)。

## 本地启动

先安装纯推理与服务依赖：

```powershell
uv sync --extra inference --extra serve
```

设置模型目录后启动仅允许本机访问的开发服务：

```powershell
$env:ANITOPY_MODEL_DIR = "artifacts\releases\anitopy-ml-v11"
$env:ANITOPY_DEVICE = "auto"
uv run anitopy-ml-webapi --host 127.0.0.1 --port 8000
```

可通过以下环境变量调整运行行为：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `ANITOPY_MODEL_DIR` | `artifacts/releases/anitopy-ml-v11` | 含权重、分词器、校准和策略文件的模型目录 |
| `ANITOPY_DEVICE` | `auto` | `auto`、`cpu` 或 `cuda` |
| `ANITOPY_MAX_BATCH_SIZE` | `100` | 单个批量请求的标题数量上限，范围 1 至 1000 |
| `ANITOPY_MAX_TITLE_LENGTH` | `4096` | 单条标题的 Unicode 字符数上限，范围 1 至 16384 |
| `ANITOPY_ALLOWED_HOSTS` | `*` | 逗号分隔的 Django Host 白名单 |

`GET /healthz` 会实际加载模型，因此只有返回 `200` 和 `{"status":"ok"}` 后才表示服务可接收请求。

## 接口示例

### 单条解析

```powershell
$body = @{ title = "[绿茶字幕组&LoliHouse] 穹庐下的魔女 / Tenmaku no Jaadugar - 09v2 [WebRip 1080p HEVC-10bit AAC][简繁日内封字幕]" } | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/v1/parse" `
  -ContentType "application/json" `
  -Body $body
```

请求体：

```json
{"title":"示例作品 S01E02 1080p"}
```

成功响应为 `{"result": {...}}`。解析结果结构与 Python `MediaParser.parse(...).model_dump()` 一致。

### 批量解析

```json
{
  "titles": ["示例作品 S01E02", "另一部作品 - 03", ""],
  "on_error": "record"
}
```

发送至 `POST /v1/parse-batch`。`record` 会在空标题等单条错误的原位置返回 `status: "error"`；`raise` 会将整个请求作为错误处理。

接口错误统一使用以下结构：

```json
{
  "error": {
    "code": "INPUT_INVALID",
    "message": "title必须是非空字符串。"
  }
}
```

输入错误返回 `400`，模型目录、依赖或设备不可用返回 `503`。

## Docker

默认构建会下载 V11 模型包和 `FacebookAI/xlm-roberta-base` 基础权重，并在镜像运行时强制离线加载：

```powershell
docker build -t anitopy-ml:v11 .
docker run --rm -p 8000:8000 anitopy-ml:v11
```

GPU 环境可追加 `--gpus all`，并在容器中设置 `ANITOPY_DEVICE=cuda`：

```powershell
docker run --rm --gpus all -p 8000:8000 `
  -e ANITOPY_DEVICE=cuda `
  anitopy-ml:v11
```

构建参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `DOWNLOAD_MODEL` | `1` | `1` 下载模型包和基础权重；`0` 不下载，适合自行构建派生镜像 |
| `MODEL_URL` | V11 GitHub Release 地址 | 模型 ZIP 下载地址 |
| `BASE_MODEL` | `FacebookAI/xlm-roberta-base` | 需要预取的基础模型名称 |
| `MODEL_DIR` | `/opt/anitopy-ml/models/anitopy-ml-v11` | 镜像内模型目录 |

当 `DOWNLOAD_MODEL=0` 时，运行方必须将完整模型目录和匹配的 Hugging Face 基础模型缓存挂载进容器，否则健康检查会返回 `503`。

## GitHub Actions

`.github/workflows/docker-image.yml` 会在 GitHub Release 发布或手动触发时，读取最新 Release 的 `anitopy-ml-v11.zip`，构建并推送镜像到：

```text
ghcr.io/coolkids/anitopy-ml:<发布标签>
ghcr.io/coolkids/anitopy-ml:latest
```

工作流需要仓库 Actions 具有 `packages: write` 权限。镜像体积会包含模型与基础权重，首次构建和推送时间较长。
